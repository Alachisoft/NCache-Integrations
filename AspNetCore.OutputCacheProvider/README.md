# NCache Output Cache Provider for ASP.NET Core

The `NCache.OSS.AspNetCore.OutputCaching` NuGet package enables ASP.NET Core applications to use NCache as a distributed backing store for Output Cache.

The integration implements ASP.NET Core's `IOutputCacheStore` interface and registers NCache through the `AddNCacheOutputCacheProvider` extension method. This allows cached HTTP responses to be shared across multiple application instances instead of being stored separately in each server's local memory.

## Overview

ASP.NET Core Output Cache is a middleware-based response caching feature that stores complete HTTP responses for cacheable requests. When a matching request is received again, the cached response can be returned directly without executing the complete application pipeline.

By default, ASP.NET Core Output Cache stores responses in the local memory of each application server. In a load-balanced environment, each server therefore maintains a separate set of cached responses.

NCache provides a distributed implementation of `IOutputCacheStore`, allowing all application instances to use the same distributed cache. Cached responses generated by one application server can therefore be retrieved and served by another server connected to the same NCache cluster.

ASP.NET Core remains responsible for determining whether a response is cacheable, generating cache keys, applying cache policies, handling expiration, and varying cached responses based on request information. NCache is responsible for storing, retrieving, and removing the resulting cached response entries.

## Key Features

- **Distributed Output Caching:** Stores ASP.NET Core HTTP responses in a distributed NCache cluster.
- **Full Response Caching:** Stores complete serialized HTTP responses for subsequent matching requests.
- **Web Farm Support:** Allows multiple ASP.NET Core application servers to share cached responses.
- **Improved Application Performance:** Reduces controller execution, database access, rendering, and other request-processing overhead.
- **Application Pipeline Bypass:** Serves matching cached responses without executing the complete application pipeline again.
- **Flexible Cache Policies:** Supports configurable expiration policies and custom caching behavior.
- **Request Variation Support:** Allows separate cache entries based on routes, query parameters, headers, and configured variation rules.
- **Tag-Based Eviction:** Allows related cache entries to be grouped using tags and invalidated together.
- **Multiple Cache Policies:** Supports different Output Cache policies with different expiration durations.
- **Configuration-Based Registration:** Supports configuration through *appsettings.json*.
- **Programmatic Registration:** Supports configuration directly in *Program.cs* through an action delegate.
- **Configurable Provider Logging:** Supports standard and detailed NCache provider logging.

## What Is Installed

Installing `NCache.OSS.AspNetCore.OutputCaching` adds the components required to use NCache as the ASP.NET Core Output Cache store.

The package provides:
- The NCache implementation of `IOutputCacheStore`
- The `AddNCacheOutputCacheProvider` extension method
- `NCacheOutputCacheOptions` for provider configuration
- NCache client libraries required to communicate with the cache cluster

The provider must be registered in the application's service collection, and ASP.NET Core Output Cache middleware must also be enabled separately.

## Prerequisites

Before using this package, ensure that you have:

1. **ASP.NET Core Application**: An ASP.NET Core application using Output Cache.
2. **Supported .NET Version**: The application must target a .NET version supported by the installed NCache release.
3. **NCache OSS 5.3.6.2 or Later**: The Output Cache provider is supported in NCache OpenSource 5.3.6.2 and later.
4. **Running Cache**: A cache, such as `demoCache`, must already be created and running.
5. **Cache Connectivity**: Every application instance must be able to communicate with the NCache servers.
6. **Required Namespace**: Include the following namespace in *Program.cs*:

```csharp
using NCache.OSS.AspNetCore.OutputCaching;
```

## Configure NCache through appsettings.json

Using *appsettings.json* is the recommended configuration approach for production environments because cache settings can be changed between deployments without modifying application code.

Add an `NCache` section to *appsettings.json*:

```json
{
  "NCache": {
    "CacheName": "demoCache",
    "EnabledLogs": false,
    "EnableDetailLogs": false,
    "ServerList": [
      {
        "Ip": "20.200.20.39",
        "Port": 9800
      }
    ]
  }
}
```

The cache specified by `CacheName` must already exist and be running.

You can add multiple entries to `ServerList` when the application can connect to more than one NCache server.

Register ASP.NET Core Output Cache and bind the NCache provider to the configuration section in *Program.cs*:

```csharp
using NCache.OSS.AspNetCore.OutputCaching;

var builder = WebApplication.CreateBuilder(args);

// Configure Output Cache policies
builder.Services.AddOutputCache(options =>
{
    options.AddBasePolicy(policy =>
        policy.Expire(TimeSpan.FromSeconds(30)));
});

// Register NCache as the Output Cache provider
builder.Services.AddNCacheOutputCacheProvider(
    builder.Configuration.GetSection("NCache"));

var app = builder.Build();

// Enable Output Cache middleware
app.UseOutputCache();

// Configure a cacheable endpoint
app.MapGet("/", () => "Cached response")
   .CacheOutput();

app.Run();
```

`AddOutputCache()` registers and configures ASP.NET Core Output Cache, while `AddNCacheOutputCacheProvider()` configures NCache as its distributed storage provider.

`app.UseOutputCache()` must also be added to the request pipeline before cached endpoints can use Output Cache.

## Configure NCache through Program.cs

You can configure the provider directly in *Program.cs* by passing an action delegate to `AddNCacheOutputCacheProvider`.

```csharp
using NCache.OSS.AspNetCore.OutputCaching;

var builder = WebApplication.CreateBuilder(args);

// Configure Output Cache policies
builder.Services.AddOutputCache(options =>
{
    options.AddBasePolicy(policy =>
        policy.Expire(TimeSpan.FromSeconds(30)));
});

// Register NCache as the distributed Output Cache provider
builder.Services.AddNCacheOutputCacheProvider(options =>
{
    options.CacheName = "demoCache";
    options.EnabledLogs = false;
    options.EnableDetailLogs = false;

    options.ServerList = new List<NCacheOutputCacheOptions.ServerConfig>
    {
        new NCacheOutputCacheOptions.ServerConfig
        {
            Ip = "20.200.20.39",
            Port = 9800
        }
    };
});

var app = builder.Build();

// Enable Output Cache middleware
app.UseOutputCache();

// Configure a cacheable endpoint
app.MapGet("/", () => "Cached response")
   .CacheOutput();

app.Run();
```

This approach is useful when the application needs to configure the NCache provider programmatically during startup.

## Configure Multiple Output Cache Policies

ASP.NET Core Output Cache supports multiple cache policies with different expiration durations.

Configure named policies through `AddOutputCache`:

```csharp
builder.Services.AddOutputCache(options =>
{
    options.AddPolicy("short", policy =>
        policy.Expire(TimeSpan.FromSeconds(10)));

    options.AddPolicy("long", policy =>
        policy.Expire(TimeSpan.FromMinutes(5)));
});
```

The required policy can then be applied to individual endpoints according to the application's caching requirements.

NCache acts only as the distributed backing store. Policy selection and expiration handling are managed by ASP.NET Core Output Cache.

## Enable Output Caching

After registering the NCache provider, add Output Cache middleware to the application pipeline:

```csharp
app.UseOutputCache();
```

You can then use the standard ASP.NET Core Output Cache APIs to identify cacheable endpoints.

For Minimal APIs:

```csharp
app.MapGet("/cached", () =>
{
    return $"Generated at: {DateTime.UtcNow}";
})
.CacheOutput();
```

For controller actions, use the standard `[OutputCache]` attribute:

```csharp
[OutputCache]
public IActionResult Index()
{
    return View();
}
```

The endpoint caching API itself is provided by ASP.NET Core. NCache serves as the distributed store for the response entries generated by the Output Cache middleware.

## How the Output Cache Provider Works

When a request is received for a cacheable endpoint:

1. The request enters the ASP.NET Core application pipeline.
2. Output Cache middleware determines whether the request can use Output Cache.
3. A cache key is generated from request information such as routes, query parameters, headers, and configured variation rules.
4. NCache is queried for an existing response associated with that key.
5. If no cached response exists, the request continues through the application pipeline.
6. The application generates the HTTP response.
7. Output Cache middleware determines whether the generated response is cacheable.
8. The serialized response is stored in NCache through the `IOutputCacheStore` implementation.
9. The cached response becomes available to every application instance connected to the same NCache cluster.

For subsequent matching requests:

1. Output Cache middleware generates the corresponding cache key.
2. NCache is queried for the cached response.
3. If a matching entry exists, the cached response is returned immediately.
4. Controller execution and downstream application processing are bypassed.
5. If no matching entry exists, the request is processed normally and a new response can be stored.

Cache key generation, cacheability checks, expiration handling, request variation, and cache policies are managed by ASP.NET Core Output Cache. NCache handles distributed storage, retrieval, and removal of the cached response entries.

## Validation

Before running the application, verify the following:

- NCache OSS 5.3.6.2 or later is being used.
- The configured cache exists.
- The cache is running.
- Every application instance can connect to the NCache cluster.
- `NCache.OSS.AspNetCore.OutputCaching` is installed.
- The `NCache.OSS.AspNetCore.OutputCaching` namespace is included.
- `CacheName` specifies an existing cache.
- Each configured server contains a valid IP address.
- Each configured server port is between `1` and `65535`.
- `AddOutputCache()` is registered in the service collection.
- `AddNCacheOutputCacheProvider()` is registered after configuring the application services.
- `app.UseOutputCache()` is added to the request pipeline.
- Output Cache is enabled on the required endpoints through `.CacheOutput()`, `[OutputCache]`, or the application's configured policies.
- Sliding expiration is not configured because it is currently unsupported.

If the cache does not exist, is not running, or cannot be reached, the NCache Output Cache provider cannot store or retrieve cached responses.

## Best Practices

- Use *appsettings.json* for production configuration when cache settings may vary between deployments.
- Use the same distributed cache across application instances that need to share Output Cache entries.
- Configure multiple NCache server addresses when appropriate for the deployment.
- Define Output Cache policies according to the expected lifetime of each type of response.
- Use named policies when different endpoints require different expiration durations.
- Use request variation rules when responses differ based on routes, query parameters, or headers.
- Use tags to group related cache entries that need to be invalidated together.
- Enable detailed provider logs only while diagnosing initialization or runtime issues.
- Keep Output Cache server configuration separate between development, testing, and production environments.
- Test caching behavior across multiple application instances before deploying to a load-balanced production environment.
- Ensure that the NCache cluster has sufficient capacity for the expected volume of cached HTTP responses.
- Do not configure sliding expiration because it is currently unsupported.
